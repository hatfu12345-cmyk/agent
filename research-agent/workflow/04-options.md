# Этап 4. Варианты

Цель: `options.md` — не меньше трёх **содержательно разных** вариантов с сильными возражениями.
Метод: `knowledge/methods/options-and-objections.md`.

## Обязательно
- **Вариант «Оставить как есть»** (`Тип: статус-кво`) — честно: что будет, если ничего не делать.
- **Вариант «Закрыть направление / прекратить»** (`Тип: закрыть`) — если применимо; если неприменимо — объясни почему в одной строке.
- Минимум один **активный** вариант. Варианты различаются механизмом, а не силой («сделать больше пушей» и «сделать меньше пушей» — один вариант).

## Для каждого варианта
```
## Вариант N: Название
Тип: статус-кво | закрыть | изменение
Суть: 1–2 строки — что делаем.
Механизм: почему это должно сработать (со ссылками на C#).
Факты за: [ФАКТ]/[ДАННЫЕ] с C#/S#
Гипотезы и прогнозы: [ГИПОТЕЗА]/[ПРОГНОЗ] с допущениями
Затраты и риски: деньги, время, команда, необратимость
### Сильные возражения
- Самое сильное возражение (как сформулировал бы умный противник), и чем оно подкреплено.
- …
Что должно быть правдой, чтобы вариант был лучшим: …
```

## Процесс
1. Сгенерируй 5–7 кандидатов, оставь 3–5 самых разных.
2. Возражения — через субагента `critic` (Claude Code) или отдельный промпт:
   «Ты скептичный руководитель. Найди 2–3 самых сильных возражения к каждому варианту».
3. Сводная таблица в конце: вариант × (ценность для аудитории, затраты, риск, обратимость, уверенность).
4. **Точка с человеком:** покажи таблицу и свою предварительную рекомендацию, попроси выбрать.

## Готово, когда
`check` проходит; человек выбрал вариант (записать в `state.md: chosen_option:`).
