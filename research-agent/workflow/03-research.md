# Этап 3. Исследование → проверяемая картина

Цель: `picture.md` — что известно, откуда, чего не знаем и почему.
Методы: `knowledge/methods/evidence-grading.md`, `jtbd.md`, `data-analysis.md`, `ux-review.md`.

## Шаги
1. **План от вопросов.** Для каждого вопроса из брифа: какой ответ изменил бы решение и как?
   Вопросы, ответ на которые решение не меняет, — не исследуй (запиши «вне фокуса»).
2. **Сопоставь источники.** По каждому ключевому утверждению — минимум 2 независимых источника
   для высоких ставок. Расхождение → разберись в причине (определение метрики, период, выборка, платформа).
3. **Свои данные** считай скриптом (`agent.py retention …` или свой скрипт в `projects/<slug>/analysis/`),
   результат регистрируй как источник с путём к скрипту. Проверяй единицы, периоды, пропуски.
4. **Запиши утверждения** с ID `C1, C2…` и метками (AGENTS.md §5):
   `- [ФАКТ] (C3) Текст. [S2, S5]`
5. **Честные пробелы:** `- [ПРОБЕЛ] (C9) Не знаем X — причина: нет доступа к Y. Влияние: может сменить выбор между В1 и В2.`
6. Если пробел может изменить решение и его можно закрыть у пользователя — спроси (1 вопрос).

## Структура `picture.md`
Короткий вывод (3–5 строк) · Что известно (ФАКТ/ДАННЫЕ) · Гипотезы (с проверкой) ·
Противоречия источников · Пробелы · Что это значит для решения.

## Готово, когда
`check` проходит (у каждого ФАКТа есть существующий S#, у пробелов — причина).
`state.md`: `stage: 4-options`.
